# Design patterns

| Task | Pattern |
| --- | --- |
| Enter or adjust a numeric value | [Number fields](number-fields.md) |
| Choose or change an editing presentation | [Editors](editors.md) |
| Add row actions, selection, or contextual section menus | [Actionable lists](lists.md) |
| Iterate on a screen study | [Design studies](design-studies.md) |

These are adopted interaction contracts for applicable tasks. Product standards
bind them to components and domain policy; adopting a contract does not certify
an existing screen. Candidate variants remain labelled proposed until accepted.

Pattern documents own selection, behavior, and acceptance. Component APIs remain
in source. Reusable demonstrations live in developer-tools' mobile lab; observed
product evidence records a revision/platform rather than proving all variants.
Runtime-specific exceptions belong beside the affected adapter or its runbook.
