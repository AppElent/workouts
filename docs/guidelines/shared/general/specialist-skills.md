# Specialist skills

Read project standards first. Use installed specialist skills only for the relevant task; load referenced rules selectively. Keep deliberate product choices and project-owned components. Report evidence-backed accessibility, correctness, or data-loss problems even when their cause is a project rule; propose a correction at its owner.

- Expo skills: Expo APIs, Router, native UI, builds, upgrades, and SDK-specific workflows. Check compatibility with the installed SDK.
- Vercel React Native skills: relevant list-performance, rendering, animation, and native-interaction techniques. Evaluate prescriptions against the project's versions and actual workload.
- better-* skills: use a focused skill for a focused change. Use better-interface for a requested broad interface review; it depends on six domain skills. Report missing domains rather than claiming full coverage.
- Browser-specific advice (CSS, DOM, ARIA) is not a native implementation recipe. Apply the appropriate platform equivalent and verify it on that platform.

Keep external skills under their existing installer/plugin owner. Do not duplicate them into this repository or silently install dependencies. Capture useful general lessons as developer-tools issues when requested; do not automatically promote them into shared policy.
